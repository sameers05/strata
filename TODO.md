## Known Issues / Watch
- **~~Intermittent malformed row HTML after delete~~ — root cause found and fixed (master-detail panes, Phase 6/create flow)**: The originally-reported sighting (a row's DOM showing orphaned `<td>` elements outside a `<tr>`, noticed during manual delete testing) is very likely explained by a confirmed, now-fixed bug in the **create** routes, not delete itself: `create_project`/`create_group_task` appended the new row via `hx-swap-oob="beforeend:#...-list-body"` (later briefly changed to `innerHTML:#...-list-body` for the empty-list case) — per htmx's own docs, "the encapsulating tag pair will be stripped for all strategies other than `outerHTML`," so this was silently dropping the `<tr>` wrapper and inserting bare `<td>` elements directly into the tbody on every create. All prior server-side diagnostics only checked the raw HTTP response text (well-formed as text), never actual client-side htmx DOM processing, which is why it wasn't caught sooner. Fixed by re-rendering the entire `<tbody>` as a single `hx-swap-oob="true"` (default outerHTML, tag-preserving) fragment on every successful create, matching the same mechanism already used for the per-row edit/update case. Delete's own OOB usage (`hx-swap-oob="delete"` / `"true"`, both id-matching, non-selector forms) was independently confirmed safe and was never affected. If malformed rows are still seen after this fix, it's a genuinely new issue — capture the raw Network "Response" tab output (not DOM inspector) immediately when it happens.
